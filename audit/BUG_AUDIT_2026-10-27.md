## CONFIRMED FINDINGS

### HIGH

**F1. `detectSalesDuplicates` crashes every run → workflow auto-disabled; duplicate detection dead ≥24 days**
- Live evidence: workflow `statusReason: "consecutive_failures"` → platform auto-paused after 5 crashes; every run since 2026-10-03 fails `HTTP 500 "user worker threw an exception"` (58–171s before death).
- Code: `base44/functions/detectSalesDuplicates/entry.ts` — **no outer try/catch** (unlike siblings); O(n²) pair loop over up to 10k WorkOrders (~3,100 real); per-flag `loadAllEntityRows` fan-out on create path. Likely CPU/timeout or rate-limit kill.
- Fix: outer try/catch + structured 500; bucket pairs before O(n²) or chunk with a cursor; then re-enable workflow.
- Reproduced: live run history. Confidence: confirmed (crash certain; exact exception unknown — needs manual run/platform worker logs).

**F2. Admin → Permitting "batch jurisdiction research" 100% broken — two independent defects**
- `src/pages/AdminPermittingSettings.jsx:66,84` invokes `'permittingproxy'` — deployed name is `permittingProxy`. **Live-verified: function routing is case-sensitive** — `permittingproxy` → `404 "not found or not deployed"`, `permittingProxy` → `401` (routes).
- Also `request.id` reads the invoke envelope wrong: `functions.invoke` resolves `{data}`; must be `request.data.id` — else poll posts `id:undefined` → 400.
- Plus `handleBatchUpdate` (L123-128) has no try/finally → failure leaves permanent "Updating…" spinner.
- Fix: `'permittingProxy'` + `request?.data?.id` + try/finally.

**F3. Customer portal invoices show $0.00 for every line, tax row hidden, description missing**
- `customerPortalAction/entry.ts:63-73` `invoicePortalView` reads `item.amount`, `invoice.tax`, `invoice.description`.
- Writers/schema: line items carry `line_total` (`invoicingAction:36-50`), tax is `tax_amount` (Invoice.jsonc:79), description is `notes` (jsonc:102). Verified end-to-end incl. `src/pages/CustomerPortal.jsx:120-148`.
- Every customer-facing invoice link misstates line amounts; tax invisible. Fix: `line_total`, `tax_amount`, `notes`.

**F4. `/NewUserSetup` invite links unusable for logged-out invitees — onboarding broken**
- `onboardingAccountAction/entry.ts:69` emails `…/NewUserSetup?token=…`; the page renders inside `Layout` → `LoginGate` (`src/components/auth/LoginGate.jsx:15-60`) which swallows ALL clicks/keys for session-less users and opens sign-in instead. Only `/timeclock` exempt.
- `/ResetPassword` deliberately bypasses Layout (`App.jsx:167`); NewUserSetup didn't get the same treatment.
- Fix: explicit pre-PAGES route rendering NewUserSetup without LayoutWrapper, or exempt `/newusersetup` in LoginGate.

**F5. Backend functions collectively saturate the Base44 `entity_list` rate limit — ongoing user-facing 500s**
- Live `logs --level error` (today 09:40–09:42, a normal window): `entity_list allows 140 requests per 60s` errors across `smartsheetSyncAction`, `timeClockAction`, `manageAnnouncements`, `opportunityWorkspaceAction`, `staffDataRead`, `verifySession`. The limit is per-caller; all service-role traffic shares one budget while ~5 schedulers + user traffic contend.
- Impact: intermittent 500s for staff; retry logic papers over most but bursts get through. This is systemic, not a single bug.
- Fix: consolidate reads, add caching/queue pacing beyond `withEntityRateLimitRetry`, reduce scheduler overlap (Bouncie sync q5m + notify worker q10m + backlog refill q15m + smartsheet q15m ×2 + user sessions).

**F6. Dead "Calendar" nav item → every user hits PageNotFound**
- `src/Layout.jsx:93` `meetingsDropdownItems` → `createPageUrl("WorkOrderCalendar")`; page deleted (components in `src/components/calendar/` orphaned). Also broken in split-view (`MultiPageView` map) and mobile "All Pages" (`Layout.jsx:1615`).
- Found independently by reviewers A and E. Fix: remove item or repoint.

**F7. `monitorJurisdictionChanges` scans all ~3,106 jurisdictions with an LLM call each — can never finish; head-of-list rescanned forever**
- `entry.ts:95-99` loads ALL JurisdictionProfile rows (`-updated_date`); `:106-250` loops an agent invoke per row. Timeout kills run after a handful; updated rows re-sort to the top → same head next run; tail never monitored; large LLM spend for ~zero coverage.

**F8. Fleet meter-based maintenance generation silently dead**
